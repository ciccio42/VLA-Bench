VLA-Bench runs VLA policies in a UR5e **pick-and-place** world. There are 4 colored boxes, 4 bins and 16 task variations. The benchmark then changes one thing at a time: **which object goes into which bin**, **where objects spawn**, **what they look like**, or **how the instruction is phrased**. For every rollout it reports three nested metrics: 🎯 **Reached**, ✋ **Picked** and ✅ **Success**. Grasps of the wrong object are logged separately, so you can tell *"can't manipulate"* apart from *"misunderstood the instruction"*.

## ✨ Highlights

- **One harness, five model families.** OpenVLA-OFT, TinyVLA, LeRobot policies (MolmoAct2, VLA-JEPA), mimic-video and Interleave-VLA all use the same rollout loop, seeds and metrics.
- **Plug in any policy over HTTP.** Models whose dependencies clash with the simulator run as a small inference server in their own env.
- **Controlled generalization axes.** Compositional, unseen-object, spatial, visual and linguistic shifts. Commands can even be generated by a VLM watching a *human* demonstration.
- **Reproducible and resumable.** There is a fixed seed list, every episode is saved as `.pkl` + `.mp4` + `info.json`, and finished episodes are skipped on re-run.
- **Built for SLURM.** One `sbatch` launcher per model family.

## 🧪 Generalization axes at a glance

| Axis | Task suite / flag | Held out |
|---|---|---|
| Compositional | `ur5e_pick_place_delta_removed_0_5_10_15` + `otd` | Diagonal object→bin pairs |
| Unseen object | `ur5e_pick_place_rm_12_13_14_15` + `otd` | Every red-box task |
| Spatial | `ur5e_pick_place_{removed_spawn_regions, rm_one_spawn, rm_central_spawn}` + `--change_spawn_regions` | Spawn regions |
| Visual | `--object_set N` | Object appearance |
| Language | `--change_command`, `use_cosmos_name` | Paraphrases and VLM-generated commands |

## ⚡ Quickstart

```bash
# 1. Install MuJoCo 2.1 + a simulator env (see docs/01_installation.md)
cd robosuite_test
conda activate openvla_robosuite_1_0_1

# 2. Evaluate a checkpoint on the unseen-object split
python run_robosuite_eval.py \
    --config_path models/openvla_eval_config.yml \
    --task_suite_name ur5e_pick_place_rm_12_13_14_15 \
    --model_config.model_path <your-checkpoint-or-HF-repo> \
    --model_config.otd true \
    --num_trials_per_task 10

# 3. Aggregate the results
python analyze_results.py --path <model_path>/rollout_pick_place_0_False_obj_set_-1_change_command_False_use_vllm_False_otd_True --otd True
```

## 🗂️ Repository structure

```
VLA-Benchmark/
├── docs/                         # 📚 Documentation (start here)
├── SAVE_ON_HUGGING.md            # Upload/load OpenVLA checkpoints on the HF Hub
├── setup.py                      # Makes the repo importable (`pip install -e .`)
├── robot_utils.py                # Task suites, variation splits, max steps, seeding, logging
├── openvla_utils.py              # OpenVLA-OFT loading, preprocessing, action heads
├── tinyvla_utils.py              # TinyVLA helpers
│
└── robosuite_test/               # ⭐ The benchmark itself
    ├── run_robosuite_eval.py     # Main entry point (draccus CLI): rollout loop + metrics
    ├── robosuite_utils.py        # Env builder, reach/pick/place checks, video rendering
    ├── command.json              # Language instructions per task / variation / object set
    ├── seeds/seeds.txt           # Fixed evaluation seeds
    ├── models/                   # 🧠 One adapter + one YAML config per model family
    ├── test/pick_place.py        # Pick-and-place rollout, spawn regions, success criteria
    ├── tasks/                    # multi_task_robosuite_env: arenas, objects, experts, controllers
    ├── robosuite/                # (git-ignored) patched robosuite 1.0.1
    ├── conda_environments/       # Conda env specs
    ├── python_requirements/      # Pip requirement pins
    ├── install.sh                # Installs tasks/ in editable mode
    ├── run_*.sh                  # 🚀 SLURM launchers, one per model family
    ├── analyze_results.py        # Per-object / per-bin success breakdown
    ├── create_video.py           # Re-render videos from saved trajectories
    ├── vllm_utils.py             # Cosmos-Reason2 command generation
    └── LEROBOT_EVAL.md           # Design notes for the HTTP-bridge integration
```
